## Learning goals and the discovered gap

P3 configured RS256 verification and normalized claim validation. P4.S1 proved conversion into request authorities and subsequent endpoint permission. This step tests malformed signed inputs, omitted required claims, and exact timestamp-skew boundaries. Read the [claim contract](../JWT-CLAIM-CONTRACT.md) and [P4.S1](P4.S1-WALKTHROUGH.md) first. P4.S3’s expanded diagnostics remain future work.

A valid signature proves that the signed bytes came from a trusted key; it does not make every claim representation acceptable. A timestamp validator checking a present timestamp does not establish required presence. A validator inspecting an already normalized map may also be unable to distinguish malformed original JSON from legitimate input.

The first full run of the new 45-case HTTP suite exposed three failures: `iat: null`, `nbf: null`, and numeric `sub` received 200 instead of the contract’s 401. Inspection of the installed Nimbus 9.37.4 and Spring Security 6.5.6 bytecode using javap explains the normalization gap: Nimbus JWTClaimsSet.parse accepts a numeric subject by converting it to text; Spring’s MappedJwtClaimSetConverter removes null converted timestamp entries and can synthesize iat from exp when absent. Existing normalized-map unit tests could not detect these original representations. The fix preserves the contract rather than changing it to match accidental coercion.

## Application code: strict decoding without a new authentication filter

Paths in this section are relative to `src/main/java/com/example/securitylearning/`.

### `security/StrictJwtDecoder.java`, every block

Lines 3–5 import Java’s checked parse exception and collection contracts. Line 7 imports Nimbus SignedJWT: the project continues using Nimbus’s parser, not a handwritten parser or cryptographic implementation. Lines 8–10 import Spring’s BadJwtException, decoded Jwt value, and JwtDecoder interface. Implementing this interface decorates decoding inside the existing Resource Server path. It does not replace BearerTokenAuthenticationFilter, JwtAuthenticationProvider, authentication conversion, or authorization.

Lines 12–18 declare a final class, retain a final decoder delegate, and accept it through the constructor. There is no stereotype annotation: JwtDecoderConfig constructs and returns the wrapper as its single managed JwtDecoder bean. Restricting inheritance keeps this small adapter’s behavior explicit.

Lines 20–22 implement `decode(String token)`. Calling `delegate.decode(token)` **first** performs the configured RS256 signature verification, standard decoding/conversion, and normalized issuer/audience/timestamp/schema validation. Failures propagate as Spring JWT exceptions without further payload inspection. Passing this call is not yet enough to authenticate: the wrapper must also succeed before returning to JwtAuthenticationProvider.

Lines 23–24 ask Nimbus to parse the same immutable compact string and obtain its payload as a JSON object, retaining original JSON value types and explicit nulls. This second Nimbus parse is intentional: the normalized Jwt returned by the delegate no longer preserves every distinction. It is a shape check of an already verified payload, not an alternative signature verifier. No private key is used in decoding. The parser is still the library parser; no split/Base64/string-based parser is introduced in application code.

Lines 25–29 require an object payload, a nonblank string subject, a string issuer, valid audience representation, and a numeric expiration. Optional iat/nbf are allowed to be absent, but their present values must be numeric. `Number` accepts JSON numeric forms; boolean or numeric-looking strings do not satisfy it. This layer checks representation; the delegate remains responsible for normalized required values, issuer equality, audience membership, and timestamp acceptance.

Lines 30–32 check roles only when present: it must be a JSON array/list whose elements are nonblank strings. An empty list is valid because all its elements satisfy the predicate; explicit null is invalid because it is not a list. The parentheses keep the present-roles condition grouped within the rejection expression. Failure throws BadJwtException with a fixed message rather than echoing the token or offending claim value.

Line 34 returns the **original normalized Jwt** from the trusted delegate after all checks. No authority or SecurityContext is created here. Lines 35–36 translate Nimbus’s checked ParseException into BadJwtException with a fixed top-level message. Signature/standard decoding errors from line 22 are not caught or mislabeled. BadJwtException follows the normal Resource Server invalid-token handling path. The code never logs the compact token; debug/body logging is not enabled by this project.

Lines 40–42 implement `optionalNumericDate(Map, String)`: absent key succeeds, present numeric value succeeds, present null fails. `containsKey` is necessary because `get` alone cannot distinguish absence from null. Lines 44–48 implement `audienceIsValid(Object)`: accept either a nonblank string or a nonempty list of nonblank strings. This preserves the standard single-audience JSON representation while rejecting scalars of other types, empty arrays, and mixed arrays. The delegate additionally requires the actual configured API audience.

### `config/JwtDecoderConfig.java`

Two imports add StrictJwtDecoder and JwtDecoder. The bean method at lines 44–52 now returns the interface instead of the concrete NimbusJwtDecoder. It still builds Nimbus with the RSA verification key and explicit RS256 algorithm allowlist, creates JwtTimestampValidator with 60 seconds of skew, injects the Clock, and composes normalized schema, issuer, and timestamp validators. The only behavioral addition is `return new StrictJwtDecoder(decoder)` at line 52. Consumers already depend on JwtDecoder, including the security chain and login tests, so no second authentication path or bean is needed.

Older walkthrough decoder line references describe their original checkpoints; this section is current. The application JwtClaimContractValidator remains useful for normalized required claims and schema. Its continued presence means a caller cannot bypass application validation by passing raw type checks alone.

## Test construction: preserve the wire representation

The new `src/test/java/com/example/securitylearning/JwtNegativeValidationIT.java` uses actual Tomcat HTTP. Imports at lines 3–44 cover Java fixtures/time/collections, Jackson JSON serialization, Nimbus JWS construction/signing, JUnit lifecycle/parameterization, Spring test configuration, RestAssured, Awaitility, and assertions. Jackson is only used to generate test payload JSON; Nimbus handles JWS signing and production parsing.

Lines 46–56 start `@SpringBootTest(RANDOM_PORT)` in jwt mode, explicitly import FixedTimeConfiguration, initialize the fixed 2030 instant, generate a local owner-only key fixture, inject Tomcat’s bound port and the bounded trace sink, and retain a test ObjectMapper. This is an isolated context distinct from none/basic and other JWT test configurations. Tests never contact an external issuer. Lines 58–67 register both temporary PEM paths before startup and delete the fixture in AfterAll. The existing fixture’s POSIX permissions/cleanup explanation is in [P3.S3](P3.S3-WALKTHROUGH.md).

Lines 69–83 define `invalidRawTokensFailClosedBeforeMvc`: 34 parameter values exercise a fresh valid map with one corruption each. Each request sends only a bearer header to GET `/api/user` and asserts 401, an invalid_token Bearer challenge, no session cookie, and an exact outer-only trace. It does not print response headers or full request bodies. Errors are checked through status/metadata and fixed trace events, not by asserting a secret token value.

Lines 85–102 define `timestampSkewHasDeterministicBoundaries`. Six trusted test strings identify exp/nbf, signed offset from NOW, and expected status. The test changes only that timestamp. Successful boundaries assert exact user JSON; rejected ones assert invalid_token. Both assert no cookie and appropriate completion events. No Thread.sleep or dependence on the machine’s current date is involved.

Lines 104–118 define `permittedRawRepresentationsRemainAuthenticated`: a single-string audience, absent iat, absent nbf, absent roles, and empty roles must remain valid. These positive controls guard against an overbroad “fix” that requires every optional field or rejects a standard audience form. `/api/user` needs authentication, so no-role tokens are allowed; P4.S1 separately checks their admin denial.

Lines 120–130 build a LinkedHashMap of known-good raw claims. Explicit epoch seconds preserve JSON NumericDate values. The fresh mutable map prevents a prior corruption from affecting another invocation. Lines 132–165 implement `alter`: missing-* removes a key, null-* writes explicit null, and the switch applies wrong values/types for the remaining scenarios. Null-role is distinct from null-roles: a mutable ArrayList is used because List.of disallows null. The switch’s no-op default leaves cryptographic-only scenarios otherwise valid.

Lines 167–188 implement `signed`. Malformed input returns the deliberately invalid compact string `not.a.jwt`. Other inputs become a JWSObject with an explicit RS256 or HS256 header and the ObjectMapper’s exact JSON payload. This avoids JwtClaimsSet builder normalization hiding malformed representations before they reach HTTP. HS256 uses a deterministic test-only 32-byte symmetric fixture; it is never an accepted runtime key/algorithm. Unknown-key uses another fresh RSA pair; ordinary cases use the configured matching fixture. RSASSASigner/MACSigner implement the cryptography.

The tampered scenario signs first, changes sub afterward, and replaces only the payload segment using Nimbus Base64URL while retaining the original header/signature. This compact manipulation is confined to adversarial test construction; it is not application JWT parsing. The decoder must reject integrity failure even though the replacement payload is valid JSON.

Lines 190–199 centralize the normal user callback list and `assertTrace`. Awaitility waits for completed filter publication, then prints only scenario name, server UUID, and fixed events. Lines 201–208 use nested TestConfiguration, Bean, and Primary to supply the controlled UTC clock to the actual decoder. Test methods declare checked exceptions from fixture serialization/signing rather than masking fixture failures as expected HTTP failures.

## Request lifecycle and trust boundary

Tomcat parses HTTP and supplies servlet objects through registered filters. RequestTraceFilter opens correlation outside DelegatingFilterProxy. That proxy delegates to FilterChainProxy and its jwt chain. BearerTokenAuthenticationFilter extracts the compact value and invokes bearer authentication through an AuthenticationManager/JwtAuthenticationProvider. The provider calls the configured StrictJwtDecoder, whose delegate verifies RS256 and validates normalized claims. Only after the wrapper succeeds does the provider call JwtAuthenticationConverter and return a trusted JwtAuthenticationToken. Spring Security establishes the request SecurityContext, and AuthorizationFilter checks permission.

Invalid decoding instead becomes bearer authentication failure: the built-in filter’s failure path invokes the Bearer entry point, returning 401 with invalid_token before downstream authorization/MVC. It is not an MVC controller exception, nor the same path as a valid identity denied ADMIN access (403). Normal response propagation still unwinds the outer filter and lets Tomcat finish the exchange. Nimbus alone creates no authenticated SecurityContext.

Allowed requests reach DispatcherServlet. Handler mapping selects DemoController.userEndpoint; the handler adapter invokes it, and response-body processing uses a message converter/Jackson to serialize the map. MVC interceptors run preHandle/postHandle/afterCompletion and filters unwind. None has no security proxy; Basic remains its independent password scheme. Runtime issuer/BCrypt are not called to authenticate these test bearer requests.

A configured list is membership/order evidence, not a per-filter invocation log. P4.S3 will expand those diagnostics.

## Time semantics, questions, and safe exercises

With the fixed clock and 60-second skew, exp exactly NOW−60 and nbf exactly NOW+60 pass the installed timestamp validator’s strict after/before comparisons. One second farther rejects. These observations concern this explicit skew policy and second-resolution inputs; they do not mean expiration is ignored. The 300-second issuer lifetime remains unchanged. Optional iat is descriptive metadata, not a maximum-token-age policy. Standard Spring conversion may synthesize normalized iat when the original claim is absent; acceptance tests verify omission is allowed, not that normalized output lacks iat.

Review questions:
1. Why validate original types after normalized validation? Numeric-sub conversion and null timestamp removal can erase distinctions required by the local contract.
2. Does a correct signature guarantee permission? No: issuer/audience/time/type validation, authentication creation, and authorization remain separate decisions.
3. Why do malformed roles receive 401 while empty roles can lead to 403? Malformation invalidates authentication; an empty authority set is valid authentication but cannot satisfy ADMIN.
4. Why can a locally signed HS256 token still fail? The decoder trusts only its configured RSA public key and RS256 allowlist, not an untrusted alg declaration.

Safe exercises on a disposable branch:
1. Move the exp boundary offset from −60 to −61 and predict 401; run the focused case without sleeping, then restore it.
2. Replace the positive single-string audience with an array containing the same API audience; expect the same 200 because both are accepted representations. Restore before committing unrelated changes.

Never print compact bearer values while experimenting. JWT claims are Base64URL encoded and readable, not encrypted. Resource Server works without implementing an OAuth2 Authorization Server or grant flow; no custom bearer filter or cryptographic parser is added here.
