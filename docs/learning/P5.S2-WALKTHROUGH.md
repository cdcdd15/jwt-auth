## Request-flow and test evidence

The guide reconstructs client → Tomcat → servlet filters → optional security proxy → DispatcherServlet/handler mapping/adapter/controller → message conversion and response unwind, with a Mermaid sequence diagram. P5.S1 contains three concrete mode diagrams. P4.S3 contains configured-versus-observed filter evidence. No synthetic final trace is invented to stand in for real HTTP tests.

The final-run excerpts below connect the theory to callback order. Entry/exit map to RequestTraceFilter; interceptor callbacks map to MvcTraceInterceptor; controller events map to DemoController. Security state and authorization.exit map to SecurityTraceFilter. Challenge/denied map to the configured handlers. Invalid-token authentication failure occurs before later authorization/MVC; a valid USER/admin denial occurs after authenticated conversion. Existing tests and final scans cover the exercised paths; arbitrary future logging/configuration changes would require renewed review.

## Review questions and safe exercises

1. Why was the standard Java registry insufficient? The valid Java21 compiler/runtime was bundled inside an IDE rather than registered under the system Java installations.
2. Why run clean verify? It recompiles with the chosen toolchain and executes both unit and real HTTP integration verification instead of trusting stale artifacts or package-only results.
3. Does a documentation audit prove all library branches are tested? No; it proves source-to-teaching coverage and records actual tests, with explicit evidence limits.
4. Why preserve historical counts? They record the learning progression; current summaries must clearly distinguish them from final source/runtime evidence.

Safe exercises:

- On your own machine, run mvn -version using your Java21 JAVA_HOME before verification. Confirm both Maven and test startup identify Java21; do not assume compiler release alone proves runtime.
- Choose one final trace event, locate its current source in COMPLETE-GUIDE’s audit index, and run its owner IT case. Predict which markers disappear if security rejects earlier; never enable Authorization/body logging to inspect the token.
